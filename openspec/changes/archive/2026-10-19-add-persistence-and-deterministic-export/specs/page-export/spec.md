# Spec Delta

## Purpose

Publishes portable, reproducible representations of locally stored pages in a directory chosen by the user.

## ADDED Requirements

### Requirement: Three page formats
The system SHALL export each selected non-empty page as one JSON, one SVG, and one Markdown file without cloud access. Users SHALL NOT need to select formats.

#### Scenario: Export a stored page
- **WHEN** the user exports a page containing strokes
- **THEN** the destination contains a JSON record, an SVG drawing, and a Markdown page for that canonical page

#### Scenario: Selected page is empty
- **WHEN** a selected page has no stored strokes
- **THEN** the export creates no files for that page

### Requirement: Deterministic bytes
For the same canonical page and stroke multiset and export format version, the system SHALL produce byte-identical files regardless of import order, process restart, or live/offline source. Exported data SHALL contain the four page components; each stroke's origin-time reliability and reported milliseconds; and its ordered points' integer x, y, time offset, and pressure. It SHALL omit source, host timestamps, storage IDs, and batch IDs.

#### Scenario: Re-export unchanged page
- **WHEN** an unchanged page is exported twice
- **THEN** each corresponding output file has identical bytes

#### Scenario: Import order and source differ
- **WHEN** the same canonical strokes are stored in a different order or arrive through a different source
- **THEN** the three files have identical bytes and preserve the multiplicity of distinct retained strokes

#### Scenario: Equal stroke content appears more than once
- **WHEN** the library retains multiple strokes with identical canonical content because their identity is unreliable
- **THEN** each occurrence appears in the exported data and its position does not depend on a storage row ID

### Requirement: Fixed page canvas
The system SHALL draw every SVG page on one declared page canvas, so that the pages of a note share a scale and an origin and can be compared or overlaid. The canvas SHALL be the notebook sheet expressed in pen coordinate units, and the drawing SHALL also declare its size in millimetres. The stroke width SHALL be a pen line rather than one pen coordinate unit.

The canvas SHALL cover the sheet and any ink past the sheet's right or bottom edge. The origin SHALL be fixed, because a moving origin would stop two pages of a note from lining up; ink past the left or top edge is therefore outside the canvas, which a normalized coordinate cannot reach because the wire format carries a `UInt16` integer part.

#### Scenario: Two pages of one note
- **WHEN** two pages of the same note are exported, one carrying a few strokes and one carrying many
- **THEN** both drawings declare the same canvas size and the same origin

#### Scenario: Ink falls past the sheet
- **WHEN** a page carries a point past the sheet's right or bottom edge
- **THEN** the canvas covers that point, no stroke is clipped, and the origin is unchanged

#### Scenario: Stroke width
- **WHEN** any page is exported
- **THEN** the drawing's stroke width is one point, which is a pen line, and not one pen coordinate unit, which is 2.37 mm

### Requirement: Complete file publication
The system SHALL publish each of the three files by atomic replacement and SHALL report export success only after all three succeed. It SHALL report the success or failure of each target file. A failed publication SHALL preserve committed library data.

#### Scenario: Write fails before replacement
- **WHEN** a temporary export cannot be completed
- **THEN** the existing destination file remains complete and the operation reports failure

#### Scenario: One of three files fails
- **WHEN** one target fails after another target has been published
- **THEN** the result identifies each published file and the failed file, and a retry can complete all three

### Requirement: Preserve existing destination files
When generated bytes differ from an existing target, the system SHALL preserve the prior file before replacing it and SHALL keep at most three prior versions per target. It SHALL leave an identical target unchanged. If preservation fails, it SHALL leave that target unchanged and report failure.

#### Scenario: Re-export unchanged content
- **WHEN** a target already contains exactly the generated bytes
- **THEN** its content remains unchanged and no backup is created

#### Scenario: Existing file differs
- **WHEN** a target contains different bytes
- **THEN** the prior bytes remain recoverable in that target's backup history and the target contains the newly generated bytes

#### Scenario: Backup cannot be preserved
- **WHEN** the system cannot preserve a differing target
- **THEN** it does not replace that target and reports its publication failure

### Requirement: Safe page identity in output
The system SHALL distinguish all four canonical page components in output filenames and content and SHALL NOT include Bluetooth addresses, pen serial numbers, or authentication material.

#### Scenario: Pages share a page number
- **WHEN** two selected pages share a page number but differ in another canonical component
- **THEN** their output paths do not collide

#### Scenario: Export content is inspected for device secrets
- **WHEN** JSON, SVG, and Markdown files are generated from a read whose transport observed device identifiers or authentication material
- **THEN** none of the three files contains a Bluetooth address, pen serial number, or authentication material
